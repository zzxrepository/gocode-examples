# Aurora AI 学习项目范围与路线

更新时间：2026-08-22。

## 项目目标

这是一个用于学习 Go + Eino + Vue 的 AI 应用，不做通用协作 SaaS。产品主线只有：

```text
用户注册/登录 → 选择下游模型 → 多轮对话 → 上传资料 → RAG → MCP 工具 → Skill 约束 Agent 行为
```

界面采用简洁的 ChatGPT 式布局：左侧历史会话、中间流式对话、底部输入与模型/能力选择。工具不常驻展开，只在输入框的“工具与 Skill”菜单中出现。

## 保留的前端能力

| 模块 | 当前状态 | 说明 |
| --- | --- | --- |
| 登录/注册/退出 | 页面和路由保护已完成 | 当前是本地演示状态；后端认证完成后替换为 JWT 调用 |
| 对话 | 已接 `GET /api/models` 与 `POST /api/chat/stream` | 支持流式回复、多轮上下文、停止、重新生成 |
| 会话历史 | 本地新建、搜索、重命名、删除、导出 | 后端完成后切换为数据库和跨端同步 |
| 模型选择 | 已接模型列表 | 后端应按当前用户返回可用下游模型 |
| 消息呈现 | Markdown、代码、复制、用户消息编辑 | RAG/MCP 结果可展示工具过程和引用 |
| 文件资料 | 选择、拖放、粘贴后的本地展示 | 实际上传、解析、文件库交给后端 |
| RAG/MCP/Skill | 选择器、预设、会话状态已完成 | 服务端执行后才会真正生效 |
| 设置 | Temperature、主题、紧凑模式 | 用户级同步等待后端 |

## 明确不做

以下功能会增加数据模型、权限、版本管理和运维复杂度，不属于当前学习目标：

- Canvas/Artifact、产物版本和代码沙箱。
- 项目工作空间、协作成员、评论、分享链接。
- 回答赞踩、对话分支、置顶/归档、复杂推荐系统。
- 图像生成、语音对话、任务调度等与 RAG/MCP 主线无关的能力。

## 为什么保留 RAG、MCP 和 Skill

RAG 解决“模型不知道你的私有资料”，MCP 解决“模型如何安全调用外部系统”，Skill 解决“在特定任务中应如何约束模型与允许哪些工具”。三者刚好覆盖一个 Agent 应用最重要的知识、能力和行为边界。

下游模型、搜索、文件或工具的选择必须由服务端真实执行。千问的联网搜索也是模型侧通过参数启用实时检索；DeepSeek 将搜索、深度思考和文件能力作为服务能力，而非前端装饰。[千问联网搜索](https://platform.qianwenai.com/docs/developer-guides/tool-calling/web-search) [DeepSeek App](https://api-docs.deepseek.com/news/news250115/)

## 后端实现顺序

### P0：身份与会话

1. 用户表、密码哈希、JWT、刷新令牌、当前用户接口。
2. 会话与消息表；列表、详情、删除、重命名、游标分页。
3. 有状态 SSE 聊天：服务端保存用户/助手消息，而不是前端每次携带无限历史。
4. 用户设置和模型权限：不同用户只能选择允许的下游模型。

### P1：资料与 RAG

1. 文件上传到对象存储，校验大小、MIME、所有权。
2. 异步 OCR/文档解析、切块、Embedding、向量检索。
3. `rag` 工具返回检索片段和引用；回答中展示来源链接。
4. 文件库列表、删除和状态查询。

### P2：MCP 与 Skill

1. MCP Server 注册、用户授权、工具 schema 与超时/重试。
2. Eino Agent 作为 MCP Client，仅按当前用户的授权调用工具。
3. 删除、发布等危险工具必须在前端确认后才执行。
4. Skill 保存为服务端可版本化配置：系统提示、可用工具、输入输出约束；浏览器只选择 skill ID。
5. 所有工具调用写入审计日志：用户、工具、参数摘要、结果、trace ID、时间。

具体路径、字段和 SSE 事件见 [API_CONTRACT.md](API_CONTRACT.md)。
